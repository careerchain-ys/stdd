# 並行作業の規律

STDD 方法論（[`stdd-methodology.md`](stdd-methodology.md)）の一章。複数のセッションやエージェントが同じリポジトリで
同時に作業するときに、互いの変更を壊さず、重複した作業を避けるための規律を定める。

## 1. 目的

AI エージェントを使うと、1 人の開発者が複数のセッションを並行して動かすことが普通になる。1 つのセッションの中でも、
オーケストレータが複数の専門エージェントを同時に起動する。このとき起きやすい問題は次の 3 つである。

- **変更の消失**: 共有している作業ツリーで、あるエージェントが変更を退避・破棄するコマンドを実行し、ほかのエージェントの
  未コミットの変更を消してしまう。
- **変更の混入**: ほかのエージェントがステージした変更や作成中のファイルが、自分のコミットに紛れ込む。
- **作業の重複と競合**: 別のセッションや作成中の PR が同じファイルを変更していることに気づかないまま着手し、
  マージのときに競合する。あるいは同じ課題を 2 か所で進めてしまう。

どれも、その場ではテストも検査も通るので気づきにくく、後になってから手戻りになる。

## 2. 規律

### 2.1 1 つのセッションにつき 1 つの作業ツリー

- セッションごとに作業ツリー（`git worktree`）とブランチを分ける。同じ作業ツリーで複数のセッションを動かさない。
- 作業ツリーは、主の作業ツリー（クローンしたディレクトリ）からの**絶対パス**で作る。相対パスで作ると、直前に移動していた
  別の作業ツリーの中に入れ子で作られることがある。入れ子の作業ツリーは、親を片付けたときに一緒に消える。
- 1 つのセッションの中でエージェントを並行して動かすときも、**自分でコミットするエージェント**（実装担当など）は、
  ほかのエージェントと同じ作業ツリーで並行させない。並行させるなら作業ツリーを分ける。

### 2.2 着手前に重なりを確かめる

- 手を付ける前に、触る予定のファイルが**ほかの作業ツリーの変更**や**作成中の PR の変更**と重なっていないかを確かめる
  （§3 のスクリプトを使う）。
- 重なりがあれば、着手する前に相手の作業の担当者と分担を決める。相手の作業ツリーのファイルを直接編集して解消しない。
- issue を起点にする作業では、issue の担当者を確かめ、自分を担当に設定してから着手する。

### 2.3 共有している作業ツリーでは、変更を退避・破棄するコマンドを使わない

作業ツリーは、ほかのエージェントと共有しているものとして扱う。次のコマンドは、ほかのエージェントの未コミットの変更を
消したり、別の場所へ移したりするので使わない。消すことが目的でなくても（編集の前に元の状態へ戻すためでも）使わない。

- `git stash`（`push` / `pop` / `apply` を含む。退避の置き場はすべての作業ツリーで共有される）
- `git checkout -- <path>`・`git restore`・`git reset --hard`
- `git clean`

代わりに次の方法を使う。

| したいこと | 方法 |
| --- | --- |
| ファイルを望む状態にする | ファイルを部分的に編集する |
| 過去の版のファイルを見る | `git show <rev>:<path>` |
| 過去の状態で動かして比べる | `git worktree add` で別の作業ツリーに取り出す |
| 変更前でも失敗するかを確かめる | 並行状況を知っているオーケストレータ（または利用者）に任せる |

### 2.4 コミットに他人の変更を混ぜない

- ステージはパスを指定して行う（`git add <path> ...`）。`git add -A`・`git add .`・`git commit -a` は使わない。
- `git add` の直後に `git commit` する。ステージしたまま別の作業を挟まない（ステージの内容は作業ツリーごとに 1 つで、
  ほかのエージェントのコミットに載ってしまう）。
- コミットの前に `git status` を読み、自分が触っていないファイルが混じっていないかを確かめる。
- 並行して動かしたエージェントの成果は、エージェントごとに別のコミットに分ける。

## 3. 自動化

### 3.1 重なりの検出

`.claude/hooks/work-overlap.sh` が、触るファイルとほかの作業の重なりを検出する（フックとしては登録しない。着手前に呼ぶ）。

```bash
# 着手前: 触る予定のファイル・ディレクトリを指定する
bash .claude/hooks/work-overlap.sh --path <path> [--path <path> ...]

# 作業中・PR の前: いまの作業ツリーの変更（主ブランチからの差分と未コミットの変更）を対象にする
bash .claude/hooks/work-overlap.sh
```

- 見るもの: ほかの作業ツリーの、主ブランチ（`project.primary_branch`）からの差分と未コミットの変更（未追跡のファイルを含む）、
  作成中（open）の PR の変更ファイル（`gh` を使う。いまのブランチの PR は除く）。
- ディレクトリを指定すると、その配下のファイルと重なる。
- 終了コード: 0 は重なりなし、2 は重なりあり、1 は引数の誤りか読み取りの失敗。どこか 1 か所でも読めなければ
  「重なりなし」とは言わない。PR を確かめない場合は `--no-pr` を付ける。
- ほかの作業ツリーの index は書き換えない。

### 3.2 限界

- 稼働中のセッションそのものは見えない。まだ何も変更していないセッションとの重なりは検出できない。
- 主ブランチは手元の追跡ブランチ（`origin/<primary_branch>`）のまま使う。古いと差分が広く出るので、必要なら先に `git fetch` する。
- open な PR は 200 本までしか読まない。200 本に達したら打ち切りの可能性として失敗にする。
- issue の担当の確認は自動化していない。issue と作業の対応のつけ方（ブランチ名、PR 本文、プロジェクトボードなど）が
  プロジェクトの運用によって異なるため。
- §2.3・§2.4 のコマンドの使用を検出するフックは、まだ用意していない。
