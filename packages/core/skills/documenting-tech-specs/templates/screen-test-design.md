# SCREEN_TEST_DESIGN.md テンプレート（feature・フロントエンド）

**目的**: [`SCREEN_DESIGN.md`](./screen-design.md) の行（画面項目・バリデーション・イベント・レスポンス処理）ごとに、
どのテストレベルで、どのテストで担保するかを 1 行ずつ定義する。`docs.lineup: layered` の構成で使う。

**配置**: `.stdd.config.yml` の `docs.layout.screen_test_design`（例: `docs/<feature>/SCREEN_TEST_DESIGN.md`）。`SCREEN_DESIGN.md` と対で作る。

**統括との分担**: ユースケースと受入基準ごとの担保先・E2E のシナリオ・テスト対象外は [`TEST_DESIGN.md`](./test-design.md) が持つ。

## 章立ての骨格

| 章 | 対になる SCREEN_DESIGN の章 | 行の単位 |
| --- | --- | --- |
| 1. 画面項目 | 2. 画面項目定義 | 表示・活性・初期値に条件を持つ項目、または値を加工して表示する項目ごとに 1 行 |
| 2. UI ロジック | 3. UI ロジック | すべての VA・EV・RS を 1 行ずつ |

## 記述基準

- **SCREEN_DESIGN の 3 のすべての VA・EV・RS を列挙する。** テストしない行も削除せず、`❌` にして根拠の列に理由を書く。
- **章 1 には、条件や加工を持つ項目だけを載せる。** 条件も加工も無い項目は対象外で、その旨を章の冒頭に 1 行書く。
- **すべての行に `ST-NN` を振る**（ファイル全体で通し番号。行を削除しても番号を詰めない）。
- **テストコードには、テスト名に行の ID と対象の ID を含める**（例: `[ST-06] [UC-<feature>-01] 作成に成功したら一覧へ移る`）。
- **テスト参照は「ファイルのパス::テスト名」で書く。** 未実装の間は `TODO`、ほかの行で担保するときは「ST-NN で担保」と書く。
- **EV の行はトリガから API の呼び出しまで、RS の行は受け取ったコードに対する挙動**を確かめる。応答を待たない変化と、応答後の挙動を同じ行に混ぜない。
- 正常系の結果の種類（0 件・作成済み返却など）を受ける RS の行は、通常の成功の行と別のテストにする。

## 記述しない内容（責務分界）

- ユースケース・受入基準の担保先、E2E のシナリオ、テスト対象外 → `TEST_DESIGN.md`
- API の操作・業務ルールの担保 → `API_TEST_DESIGN.md`
- 画面の仕様 → `SCREEN_DESIGN.md`
- セレクタ・テストデータなどの実装の詳細 → テストコード
