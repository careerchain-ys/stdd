目的:
  - この機能が解決する問題、対象ユーザー、ユーザージャーニーを SSoT として記述する
  - ステークホルダー (PM / デザイナー / プロダクトオーナー) との合意形成に用いる
  - 実装者と AI エージェントが「何を作るか (What)」を読み取れる粒度で書く

配置:
  .stdd.config.yml の `docs.layout.requirements` に従う。
  デフォルト例: docs/{{app.id}}/{{feature_path}}/REQUIREMENTS.md

含めない:
  - データモデル / 内部 API / 関数名 / クラス名 (→ TECH_DESIGN.md)
  - 実装ファイルパスや行番号
  - 実装の進捗 ("対応済み" / "実装中" などのステータス)。本書は常に最新仕様のみを保持する。

書き換え方:
  下記テンプレートのプレースホルダ ([機能名], [メインフロー名] など) を実値に置き換え、
  不要セクションは削除する。各 Journey には必ず Priority (P0 / P1 / P2) を付与する。
